## 실행과 자원

새 원문 조회는 기존 앱의 요청 코루틴 안에서 실행하며 별도 서버나 자동 시작 서비스를 추가하지 않는다. Spotify의 완전한 단어 가사를 먼저 사용하고 줄 가사가 있으면 기존 중간 결과로 표시한다. 원문이 없으면 기존 줄 제공자도 병행한다. 추가 조회 자체는 18 초 예산을 사용하며 단일 연결과 읽기에는 합계 최대 4.5 초를 적용한다. 읽는 동안 남은 시간을 확인하고 응답 크기는 4 MiB로 제한하며 연결은 종료 경로에서 닫는다.

429와 5xx 응답은 Retry-After 또는 기본 대기 시간으로 해당 서버를 잠시 건너뛰고 조회 실패를 영구적인 자료 없음으로 저장하지 않는다. 대기 상태는 프로세스 메모리에만 유지한다. 취소는 스레드 인터럽트로 전달하며 실제 기기 네트워크 취소 동작은 추가 검증 대상이다. 기존 발음 사전의 초기화와 최대 500 곡 및 30 일의 성공 캐시 정책은 바꾸지 않았다.

## 남은 기기 검증

기존 앱 위 업데이트 설치, 저장된 로그인과 설정 유지, Spotify Connect 곡 전환, 목표 커버곡의 실제 한글 발음 표시와 청취 검수는 남아 있다. 기기 검증 전까지 베타로 배포한다. 앱을 삭제한 뒤 재설치하면 안드로이드의 일반 동작에 따라 앱 데이터가 사라질 수 있으므로 기존 앱 위에 업데이트하는 방식으로 검증한다.

## 기존 앱 위 업데이트

동일한 앱 식별자와 기존 개인 서명키를 유지하고 버전 코드를 높여 덮어 설치할 조건을 확인했다. 기존 앱을 삭제하지 않고 새 APK를 연다. 기존 설정과 캐시를 바꾸는 마이그레이션은 추가하지 않았으나 실제 기기의 로그인 유지까지 확인한 것은 아니다.

2.0.1-hangul.4까지의 배포 빌드는 업데이트 저장소가 비어 있으므로 이번 APK는 직접 받아야 한다. 새 빌드에서는 기존 업데이트 기능의 저장소를 ForUltraplayer/SPOTIFY_ANDROID로 지정했다. release와 debug의 생성된 BuildConfig에서 값을 확인했다. 한글 베타를 조회 대상에 포함하고 버전과 일치하는 Myspoti-Hangul APK만 선택한다. 자동 확인 설정이 켜져 있으면 앱 실행 후 기존 3 시간 확인 간격을 적용한다. 새 버전 안내에서 다운로드와 설치를 진행하며 안드로이드 설치 확인은 사용자가 수행한다. 인증 흐름은 변경하지 않았다.

## 실행과 자원

기존 가사 조회 코루틴 안에서 재시도를 처리한다. 별도 서버, 부팅 자동 시작이나 지속 실행 서비스를 추가하지 않았다. 빌드는 --no-daemon으로 완료했고 완료 후 Java 빌드 프로세스가 남지 않은 것을 확인했다. 이번 검증을 위해 휴대폰 앱이나 별도 백그라운드 프로그램을 실행하지 않았다.

## 원본 유지 관리 검사

2026년 10월 26일에 원본 감지와 후보 준비, 검사 및 반영 도구를 추가했다. 앱 식별자와 업데이트 저장소 및 서명 연결 변경을 거부하고 충돌 표기와 후보 파일 변경을 검출하는 Python 검사 7 개를 통과했다. 원본 정식 v2.0.1이 현재 기준 커밋보다 오래된 상태와 최신 베타 v2.0.2-beta.6의 4 개 커밋 및 199 개 파일 변경을 구분해 출력했다.

최신 베타의 실제 병합 후보를 별도 work 폴더에 준비했다. CHANGELOG.md, README.md와 THIRD_PARTY_NOTICES.md의 충돌을 보고했고 해결 전 verify가 빌드를 시작하지 않고 중단했다. 실제 앱 소스는 변경되지 않았다. 이 최신 베타는 원본 고지와 문서 충돌 및 새 재생 동작 검토 후 반영할 대상으로 남긴다.

충돌이 없는 현재 기준 태그 v2.0.2-beta.4로도 후보 준비부터 전체 검사와 반영까지 실행했다. 한글 가사와 업데이트 검사 63 개에 Spotify API 및 Android 호스트 검사를 더해 JVM 검사 총 196 개가 통과했고 실패와 오류는 0 개였다. 검증한 후보를 반영한 결과 release.json에 원본 태그를 기록하는 변경만 발생했으며 앱 실행 코드와 버전 코드, 패키지 ID 및 서명 설정은 유지됐다. 자동 검사 통과는 실제 휴대폰의 재생 및 업데이트 검증과 구분한다.

Gradle은 --no-daemon으로 완료했다. 별도 가사 서버나 휴대폰 앱을 실행하지 않았고 GitHub 유지 관리 워크플로의 실행 위치와 일일 주기 및 중지 방법은 docs/MAINTENANCE.md에 기록했다. 공개 배포 APK는 2.0.1-hangul.5를 유지한다.

GitHub Windows 실행기의 전체 검사도 성공했다: https://github.com/ForUltraplayer/SPOTIFY_ANDROID/actions/runs/40276511339 . 첫 원격 실행은 SDK 준비 도구가 폐기된 tools 패키지를 요청해 실패했다. 현재 SDK 준비 도구와 platform-tools를 명시해 수정한 뒤 Python 유지 관리 검사와 전체 Gradle 검사가 모두 통과했다. 이 결과는 GitHub의 깨끗한 SDK 환경에서 확인한 빌드 및 JVM 검사이며 실제 휴대폰 검증을 대신하지 않는다.
