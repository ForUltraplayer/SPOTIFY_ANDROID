# 안드로이드 개발 계획

기존 Myspoti 한글의 한 앱 재생과 가사 화면을 유지한다. PC용 로컬 서버를 휴대폰에 연결하지 않고 앱 안의 Java 가사 엔진과 Kotlin 캐시를 사용한다. 외부 유료 API와 휴대폰 연결 없이 구현과 APK 빌드를 진행한다.

## 기준과 라이선스

기준 소스는 release.json의 upstreamCommit에 기록한 Myspoti 커밋이며 GPL-3.0 고지를 유지한다. 기존 한글 발음 수정본 위에 개선한다. ivLyrics Android 원본에서는 명시적 배포 라이선스를 확인하지 못해 그 소스나 APK를 재배포 대상으로 포함하지 않는다. 이 전용 저장소에는 base의 전체 소스와 원본 이력 및 빌드 절차를 보관한다. 서명 키, 계정과 가사 캐시는 포함하지 않는다.

## 구현 순서

1. PC의 검색 보완을 옮긴다. 제목의 feat 표기, 본문 검색, 번역 제목으로 등록된 곡과 동명 문서의 원곡 링크, 반복 횟수 표기를 처리한다. 한음의 곡 검색과 가사 행 구조도 지원한다.
2. 원문 대조를 통과한 출처만 곡명과 가수별로 학습한다. 다음 조회에서도 일본어 원문을 다시 대조한다. 캐시와 별칭은 앱 내부에만 보관한다.
3. 사용자가 켰을 때만 기존 사전을 이용해 누락 줄을 자동 보완한다. 기본값은 꺼짐이며 자동 줄 수와 출처를 가사 화면에서 확인할 수 있게 한다. 알림 팝업은 추가하지 않는다.
4. 곡 전환 취소가 다음 발음 조회를 불필요하게 막거나 실패 캐시에 남지 않게 한다. 원문 가사와 재생 시간은 유지한다.
5. 가사 화면에서 곡 제목 길게 누르기와 메뉴의 제목 복사를 추가한다.
6. JVM 검사, 실제 문서의 호스트 검사와 APK 빌드를 실행한다. 휴대폰이 필요한 설치·로그인·재생 검증은 대기한다.

## 실행과 자원

Kuromoji 사전은 처음 필요할 때만 초기화한다. 같은 엔진의 사전과 캐시는 하나의 조회가 소유하며 대기 중 취소가 가능한 잠금을 사용한다. 네트워크 조회는 시간과 문서 수를 제한하고 이전 곡의 결과를 현재 화면에 적용하지 않는다. 별도 서버, 부팅 자동 시작이나 장기 실행 서비스를 추가하지 않는다.

## 휴대폰 검증 대기 항목

현재 설치본에서 서명이 맞는 업데이트인지 확인하고 기존 로그인과 가사 설정이 유지되는지 검사한다. 이메일 로그인과 재생, Spotify Connect의 빠른 곡 전환, 검색이 실패했던 커버곡의 발음, 자동 보완 설정 및 제목 복사를 확인한다. 이런 검증은 APK 빌드나 JVM 검사로 대신 완료 처리하지 않는다. 사용자의 로그인이나 휴대폰 입력이 필요하면 설치·검증을 대기한다.

## 2.0.1-hangul.4 원문 조회 보완

PC 0.5.1에서 검증한 원문 검색 보완을 안드로이드의 별도 LyricsPlus 조회 코드에 반영한다. 원래 제목과 가수로 먼저 조회하고 feat.만 제거한 제목과 대표 가수 후보를 제한적으로 추가한다. 검색 문자열의 전각 표기와 Live 등의 버전 표기는 보존하고 비교할 때만 유니코드를 정규화한다. 니고 이름의 일본어 쉼표는 가수 구분자로 나누지 않는다.

모든 후보의 곡명과 가수 및 확인 가능한 앨범과 재생 길이를 검증한다. 응답의 신원이 없으면 같은 원천의 메타데이터로 확인한다. 429와 5xx 응답은 서버별 대기 시간을 적용하고 실패를 영구적인 자료 없음으로 저장하지 않는다. 연결은 요청 종료 시 닫고 취소 시 스레드 인터럽트를 전달한다. 한 번의 추가 조회 예산은 18 초이며 단일 연결과 읽기의 합산 제한은 최대 4.5 초다.

Spotify의 완전한 단어 가사가 있으면 이를 먼저 반환한다. 줄 가사가 있으면 기존 4 초의 단어 대기 후 이를 사용한다. Spotify 원문이 없을 때는 기존 줄 제공자도 병행하고 먼저 확보한 가사를 기존 중간 결과 경로로 표시한다. 기기에 새로운 서버나 자동 시작 서비스를 추가하지 않는다. 로그인과 가사 저장 스키마를 바꾸지 않으며 기존 앱 식별자와 서명자를 유지한다.

현재 PC에서 회귀 검사와 응답 재생 및 APK 서명 검증을 진행한다. 휴대폰 설치와 실제 곡 전환 및 한글 발음 화면의 검증은 별도 대기한다.
